# EVEING Clarune 完整离线安装候选版

目标版本：**1.0.0-rc.1**。这是一套待验证的发布候选流程，不代表已完成正式商售许可审核、代码签名或所有电脑兼容性验证。

## 用户安装与卸载

- 单个完整安装 EXE，包含通用、动漫和自然超清 Real-HAT 模型，以及相应运行环境。安装和运行不联网下载 Python、模型或依赖；不依赖原电脑上的 ComfyUI、Node.js 或开发目录。
- Windows 10/11 x64，默认安装到当前用户的 `%LOCALAPPDATA%\Programs\EVEING Clarune`，不请求管理员权限。可更改到专用的 `EVEING Clarune` 或 `EVEINGClarune` 文件夹；不允许磁盘、用户资料、文档等根目录，也不覆盖其他非空文件夹。
- 默认创建开始菜单入口；桌面快捷方式由用户勾选，初始不勾选。不修改文件关联、默认程序或浏览器设置，不添加开机自启，不附带广告或捆绑软件。
- 安装或升级同一目录前，必须自行保存结果并关闭该目录运行的 Clarune。安装器不强制结束进程。检查运行状态需要系统 WMI 服务正常可用。
- Real-HAT 需要兼容的 NVIDIA 显卡和现有驱动。驱动不随包安装，程序不会修改其他 AI 软件环境。通用引擎的 Vulkan 支持及具体 GPU 兼容性仍以实机测试为准。
- 安装包附带微软官方 Visual C++ x64 运行库安装器。若检测到缺少登记、必要 DLL，或版本低于随包运行库版本，Clarune 在安装前明确询问，默认不允许；同意后才打开微软完整交互安装界面及正常 UAC，由用户阅读并确认微软条款。取消、拒绝或失败均停止 Clarune 安装；退出码表示需要重启时，用户应自行重启后再试。不会从 System32 复制 DLL，也不会自行改系统 PATH 或安全设置。这是系统运行库的单独授权步骤，不将“用户级应用”错误宣传为无需任何系统前置条件。
- 升级使用同一应用标识与安装目录。正常卸载仅由 Inno 移除其登记的安装文件；用户配置、授权记录、队列、导出的图片均不由安装脚本删除。它们可能在重装后继续存在。
- 目前安装包未进行发行者代码签名。工具自身的有效签名不等于 Clarune 安装包已签名；Windows 可能显示未知发布者或信誉提示。

## 开发者打包顺序

1. 完成源代码测试、类型检查和编译，使 `out` 是当前 `1.0.0-rc.1` 产物。应用必须已接入生产许可校验，不使用测试公钥。
2. 通过独立注册机由管理员本人创建密码加密私钥并备份，导出 Ed25519 公钥 `license-public-key.pem`。不要在聊天、终端参数、日志中提供私钥密码。
3. 使用 `tools/stage-ai-runtime.ps1` 在专用的 `outputs/EVEINGClarune_ReleaseCandidate/resources/ai` 中准备完整 AI 运行环境。该脚本独立管理来源、哈希、依赖白名单及第三方声明；它不会被本打包命令静默运行。
   另将来自微软官方 `https://aka.ms/vc14/vc_redist.x64.exe` 的原始完整运行库安装器放入暂存目录 `Prerequisites/vc_redist.x64.exe`。脚本要求其 Authenticode 状态为 Valid、签名者为 Microsoft Corporation，并记录 SHA-256，不会在打包电脑安装它。[微软官方许可页](https://visualstudio.microsoft.com/license-terms/vs2026-ga-visualcpp-v14-redist-runtime/)链接的原始文档随包保存在 `Prerequisites/Microsoft-VC-v14-License.docx`，脚本校验固定 SHA-256。微软再分发参考声明应随 AI 许可清单保留；运行库自身安装时仍展示其条款。具备再分发资格仍需发行者核对，不由公开下载链接自动授予。
4. 将现有 Node.js 加入当前终端 PATH 后，执行：

   ```powershell
   ./tools/package-release.ps1 -PublicKeyPem 'D:/安全位置/license-public-key.pem'
   ```

   公钥参数必填。脚本校验真实 Ed25519 SPKI 公钥，拒绝私钥；调用既有 app 打包程序，保留已经暂存的 `resources/ai`，校验每个 AI 清单文件哈希，然后使用已准备好的 Inno Setup 7.1.0 离线编译 64 位安装器，采用其随附官方简体中文翻译。

5. 若应用暂存目录已经由当前源代码重新生成，只需更新公钥、文档并重新校验/编译，可添加 `-CompileOnly`；它不会重新复制应用，不会跳过版本、AI 完整性或公钥检查。不会自动判断旧 `out` 是否对应最新源码，调用者必须先完成构建。
6. 单个安装器输出到 `outputs/EVEINGClarune_Installer/EVEING-Clarune-1.0.0-rc.1-Full-x64-Setup-fix1.exe`，旁边生成哈希、公钥指纹和 AI 清单摘要证据。已有同名安装包不会被覆盖，需先人工归档旧产物。编译脚本不会运行安装器。

fix1 仅修复安装目录检查（USERPROFILE 环境变量读取及系统目录限制），应用仍为 1.0.0-rc.1。请使用默认的当前用户目录，或其他可写的专用子文件夹；不支持 Windows / Program Files 树内安装，不自动提权。

大图超清更新使用 `-InstallerRevision fix2` 输出新安装包，保留原有 fix1 文件。fix2 在单张工作区的通用/动漫模型下支持最多 1600 万像素、单边 8192 像素；输出以完整分辨率保存于临时磁盘文件，界面仅使用缩略预览。Real-HAT、批量和图片工具仍按各自原有限制运行。大图需要足够的显存、内存和临时磁盘空间；已在本机以 2556 × 5538 的合成输入完成 3× 实际模型处理，其他电脑仍需实测。

源码和脚本默认不创建生产密钥、没有万能许可证、不会强制关闭任何运行中的应用。客户包会拒绝混入私钥、注册机、客户授权文件或开发仓库。编译时依赖已审核的本地 Inno 工具与简体中文翻译，不下载编译器。

### 安装器测试专用模式

自动化安装验证可使用 `-TestOnly -PublicKeyPem '.../TEST-ONLY-public.pem'`。该开关要求公钥文件名含 `TEST-ONLY`，输出强制位于 `work/release-installer-test`，EXE 名、应用标识、默认安装目录及快捷方式均与正常包分离，不能通过此开关生成正常交付名。普通模式反过来拒绝文件名带 `TEST-ONLY` 的公钥。

测试开关不自动生成任何密钥，也不自动执行安装。测试密钥应临时生成、私钥仅保留在测试进程内；只将对应公钥用于测试包。测试后不得向客户分发测试安装器，正式打包必须重新提供管理员生产公钥。注意：测试安装器隔离的是安装目录及安装注册信息，运行应用时仍须使用测试专用用户数据目录或独立 Windows 用户，避免读取真实授权和队列。此模式会将暂存目录公钥及安装标识更新为测试值，正常打包会用明确传入的生产公钥及正常标识覆盖它们。

## 放行检查（未勾选不等于已完成）

- 全新用户安装、桌面选项、开始菜单、目录拒绝、升级、运行中阻止和卸载行为。
- 干净 Windows 缺少 VC++ 运行库时，确认提示、拒绝/取消中止、微软安装器交互/UAC、成功复查和需重启分支。当前开发电脑已具备运行库的测试不能代替此项。
- 隔离开发目录/原 Python 后，断网运行三个模型；Real-HAT 设备不支持时有可理解的错误，不静默下载依赖。
- 未激活阻止受限处理；正确机器/签名/有效期放行，错误机器、篡改、过期和续期序号回退被拒绝。
- 单张和批量、取消、关窗、保存、透明图片与中文英文界面回归。
- 卸载后用户图片和授权/队列保留；重新安装恢复策略符合产品说明。
- 最终模型/运行库完整许可审查、安装包哈希、公钥指纹核对和代码签名决策。
